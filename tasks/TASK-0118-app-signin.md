# TASK-0118: installed app browser sign-in claims

- Scope: takos-storage Phase 7, coordinated with the Takosumi app ownership migration. Takosumi owns claim issuance; this repository owns browser sessions and Drive access. No other repository is edited here.
- Authorization: match `takosumi.capsule_id` to configured `APP_CAPSULE_ID`; accept only `owner`/`member` role snapshots. An absent role permits ordinary sign-in but grants no access to the shared private Drive. Private data requests revalidate UserInfo for the same subject/exact Capsule and current owner/member role; retained tokens are encrypted in context-bound AES-GCM cookies. HMAC app-role cookies cannot grant data access. UserInfo has a ten-second deadline; expired/revoked tokens or unavailable authority deny private data, and token expiry requires sign-in again (no refresh flow added). There is no separate Storage management surface; `/api/auth/me` omits cached role snapshots so they cannot appear to be current management authority. Foreign or malformed app claims cannot use Workspace compatibility.
- Compatibility: existing Workspace-only claims and session cookies retain the configured `APP_WORKSPACE_ID` membership rule and never gain an app role. Interface OAuth requires the configured exact Capsule; Workspace evidence is optional even when legacy configuration remains; a present Workspace claim is shape-checked and matched to any configured legacy Workspace. Current audience, permission, binding and revision checks remain required.
- Runtime: both modules bind `APP_CAPSULE_ID` and optional legacy `APP_WORKSPACE_ID` independently from optional `takosumi_capsule_id`/`takosumi_workspace_id` variables. The portable module uses non-secret `vars_json`; the v2.5 manifest declares `capsule_id` and deprecated compatibility `workspace_id` context sources, which Takosumi validates and compiles into its service-owned InstallConfig mapping. The OIDC sensitive runtime recipe stays unchanged. Missing expected app ids fail closed; no inferred id or unsupported manifest field is added. Existing installs require the normal reviewed manifest/config upgrade; no live InstallConfig was changed by this source-only task.
